# Spec: Automated Impact Reaction Dataset Generator

## Overview

A hands-off pipeline that generates very large volumes of physics-driven hit-reaction
animation clips for the Kimodo training dataset. A batch picks source animations generated by
Animotive Kimodo (see FR1), plays each on a character driven by the **Physics Control**
plugin, fires parameterised impacts at it (region, intensity, size, direction, timing, bursts,
sustained force, real projectiles), lets the reaction emerge (flinch → stagger → knockdown →
ragdoll, with recovery where balance allows), bakes the resulting motion straight to a
`UAnimSequence`, and writes an auto-generated caption + sidecar JSON per clip.

**Product note:** this is a deliberate extension of the product vision. `product.md`
describes operator-driven capture of player play; this track adds *synthetic* generation with
no operator in the loop. `product.md` gains a "Synthetic impact generation" feature section and
`tech-stack.md` gains the new module and dependencies **before** implementation (workflow rule 2).

## Functional Requirements

### FR1 — Batch definition (data asset)
- `UImpactBatchDefinition` data asset holds:
  - source animation set (explicit list and/or folder + skeleton filter + tag filter), with
    loop / play-once flag and start-time sampling;
  - character setup: skeletal mesh, physics asset, Physics Control profile set;
  - impact parameter distributions (FR3) and the clip count or "full grid" mode;
  - batch seed, output root folder, clip timing (pre-roll, max reaction, settle).
- **Source motion is Kimodo-generated, not Epic's sample clips** (user, 2026-10-13: "replace
  Epic"). `tools/kimodo-impact-sources.py` writes a KimodoBatch manifest for looping clips on the
  UEFN mannequin: a forward run held to a steady pace by a dense `root2d` path
  (`smooth_root_2d`, one key per frame), speed at most 7 m/s over under 20 m, and an idle held
  at the origin the same way. Generated against the local Kimodo server, not the hosted backend.
  Authored poses can sit outside the physics asset's joint limits, so folds are measured beyond
  the source pose (FR2), not beyond the bare asset limits.
- Every clip is a pure function of `(batch seed, clip index)` → reproducible, and its
  parameters are fully recorded in its sidecar.

### FR2 — Reaction character
- Dedicated spawned actor (not the player pawn): skeletal mesh + single-node anim playback of
  the source clip + `UPhysicsControlComponent` driving bodies toward the animated pose.
- Root motion from the source clip moves the actor so locomotion clips travel; on ragdoll, the
  baked root bone follows the pelvis ground projection.
- Arena: flat ground fixture level shipped with the plugin's test content (no client content
  edited).

### FR3 — Impact parameter space

**Impactor archetypes (added 2026-10-12).** Every hit is delivered by a named *impactor*,
sampled from a project-editable catalog (data, not code). An archetype defines what the hit
*represents* and its physical character:
- `id`, display noun phrase used in captions ("a small bullet", "a thrown baseball", "a car"),
  and a one-line plain-language description;
- physical size (characteristic dimension, cm) and shape;
- mass range (kg) and speed range (m/s), from which impulse is derived — not picked
  independently, so a bullet and a car never share an impulse by accident;
- contact radius range and default delivery mode;
- verb set for captions ("shot", "hit", "punched", "kicked", "shoved", "struck", "rammed").

Starter catalog: small bullet, rifle round, shotgun blast (multi-pellet burst), thrown stone,
baseball, football, punch, kick, shove, sports tackle, swinging bat, car bumper, wrecking
ball, sustained wind/water push. Weights per archetype are set in the batch.

Each clip then samples:
- **Body region:** head, neck, chest, abdomen, pelvis, upper/lower arm L/R, hand L/R,
  thigh/shin L/R, foot L/R (mapped to physics bodies via a per-skeleton region table).
- **Impactor:** archetype from the catalog; mass, speed, radius drawn within its ranges.
- **Intensity:** derived from the resulting impulse into descriptive buckets (tap / light /
  medium / heavy / knockdown / extreme) used in captions and the report; not sampled
  independently.
- **Size:** contact radius from the archetype (point → fist → shove → vehicle-scale area),
  distributing impulse across affected bodies.
- **Direction:** sampled on a sphere relative to character facing (front/back/left/right/
  above/below + oblique).
- **Timing:** normalised phase in the source animation when the first hit lands.
- **Delivery mode:** archetype default, optionally overridden by batch weights: instant
  impulse | multi-hit burst (2–N hits, spacing sampled) | sustained force over a duration |
  physical projectile actor (shape and size from the archetype, mass, velocity) that actually
  collides.

### FR4 — Reaction and outcome
- Physics Control strength profile sampled per clip (stiff → loose).
- Outcome emerges from physics; a detector classifies it from pelvis height, CoM vs support
  polygon, and control-blend state: `flinch` | `stagger` | `knockdown` | `ragdoll`.
- Recoverable hits blend control strength back to the animation. Balance lost → full ragdoll
  until settled (velocity threshold held for N frames).
- **High-impact hits go to full ragdoll** (added 2026-10-12): above a recoverable threshold
  (impulse relative to body mass and the struck body's mass) controls release completely and the
  body ragdolls until settled, with no recovery.
- **Tripping** (added 2026-10-12): a hit to a leg of a moving character (e.g. a shot to the foot
  while sprinting) disrupts that leg's stride; when the body's momentum carries it past a support
  the feet can no longer catch, the character falls (forward for a trip) and ragdolls. Moving
  characters get the same capture-point balance check as standing ones, so a runner can stumble,
  recover, or fall. The outcome records the trip, and the caption says so ("…is shot in the foot
  while sprinting and trips, falling forwards").
- Clip window = pre-roll + reaction + settle/recover, capped by a max-reaction ceiling;
  hitting the ceiling is recorded, not silent.

### FR5 — Recording and bake
- Fixed simulation step (configurable, default 60 Hz; physics substeps independent).
- Per step, component-space bone transforms written to a buffer pre-reserved at clip start
  (no per-frame heap allocation).
- On clip end, bake to `UAnimSequence` on the source skeleton via `IAnimationDataController`,
  saved under `<OutputRoot>/<BatchName>/<ClipId>`.
- Clip IDs are deterministic hashes of the clip parameters.

### FR6 — Labels and sidecar
- Sidecar JSON per clip, **schema v3** (additive over v2): `clipSource: "synthetic_impact"`,
  raw input layers absent (not zero-filled), new `impact` block — source anim + start time,
  every hit (frame, impactor archetype id + noun + description + size + mass + speed, region,
  body, world/local direction, impulse, radius, mode, projectile spec), control profile,
  detected outcome + outcome frame, seed.
- **Human-language description of what happens**, generated per clip for training: subject +
  source motion + impactor + region + direction + outcome, e.g.
  *"A person is shot in the foot with a small bullet while running and stumbles but keeps
  going."*, *"A person walking is rammed from the left by a car and is thrown to the
  ground."*, *"A person standing idle is punched in the face from the front and staggers
  backwards."* Multiple template phrasings per slot so captions are not one fixed sentence
  shape. Source motion words come from a per-animation description table (data), falling
  back to a name-derived phrase.
- Tags: `impact`, impactor id, region, outcome, intensity bucket, source-motion type.
- Clips flagged invalid (physics explosion, NaN, interpenetration with ground beyond
  threshold, ceiling hit) are written with a reason or discarded per batch setting.

### FR7 — Execution hosts
- **Panel (PIE):** select a batch asset, Preview N clips in real time with debug draw of
  hit points/forces, Start/Stop a full run, live counters (done / invalid / per outcome).
- **Commandlet / headless game run:** same runner, fixed timestep as fast as possible,
  `-Batch=<asset> -Start=<i> -Count=<n>` for sharding across processes.
- **Resumable:** a batch manifest records completed clip IDs; rerun skips them. A crash mid-
  batch loses at most the in-flight clip.

### FR8 — Dataset distribution report
- Per batch: counts per region / intensity / mode / outcome / source anim, written to the
  manifest, so imbalance is visible before training.

### FR9 — FBX export with BONES-SEED-format metadata (added 2026-10-14)
The dataset ships as FBX files with metadata laid out like the BONES-SEED dataset
(`seed_metadata_v004.csv`, 51 columns), so it can sit beside SEED-trained data. The uasset
sidecar (FR6) stays; the export is a separate, resumable pass over a finished batch.
- **Motion files**: one FBX per valid clip (UEFN mannequin skeleton, the clip's own frame
  rate), at `uefn/fbx/<YYMMDD>/<filename>.fbx`, `<YYMMDD>` the batch's export date. Invalid
  clips are not exported.
- **Metadata CSV** `metadata/impact_metadata_v001.csv`: the 51 SEED v004 columns in SEED's
  order, then impact columns prefixed `impact_` (clip id, batch, seed, clip index, source
  animation, impactor id, region, body, direction label and vector, intensity, reaction
  impulse, mass, speed, delivery mode, outcome, outcome frame, steps, trip, overwhelmed, fps).
  Column mapping:
  - `move_name`, `filename`: the readable clip name (`IMP_000123_…`), no extension.
  - `move_duration_frames`: frames in the FBX.
  - `package` `Interactions`, `category` `Impact Reactions` (new SEED-style value).
  - `is_neutral` `1.0`, `is_mirror` `False`.
  - `move_soma_*` and `move_g1_path` empty (no SOMA/G1 version); the FBX path goes in an added
    `move_uefn_mannequin_fbx_path` column, named like SEED's `move_<skeleton>_path` columns.
  - `take_name` the batch name, `take_actor` `SIM`, `take_org_name` the source animation,
    `take_date` YYMMDD, `take_day_part` `_1`.
  - `content_name` `<source>_<impactor>_<region>`; `content_natural_desc_1..4` four different
    caption phrasings (FR6 templates, distinct random choices); `content_technical_description`
    impactor, mass, speed, impulse, region, direction, outcome in plain words;
    `content_short_description` e.g. `shot in the foot while running, stumbles`;
    `content_short_description_2` `impact reaction`.
  - `content_all_rigplay_styles`, `content_uniform_style` `neutral`.
  - `content_type_of_movement` the source motion in SEED's vocabulary (`standing idle`,
    `walking`, `jogging`, `running`, `jumping`, crouch walk `walking`) plus `, falling` when the
    outcome is a knockdown or ragdoll.
  - `content_body_position` `standing` or `crouching`, plus `, lying` when the character ends
    on the ground.
  - `content_horizontal_move` 1 when the source travels or the character steps; `content_vertical_move`
    1 for a jump source or a fall; `content_props`, `content_complex_action`, `content_repeated_action` 0.
  - `actor_*` the mannequin's measurements from its reference pose (height, foot, collarbone,
    hips, knee, ankle heights; collarbone, elbow, wrist, shoulder, hip spans), `actor_uid`
    `UEFN_Mannequin`, `actor_weight_kg` the batch's character mass, `actor_height` S/M/T by
    SEED's bands, `actor_profession` `synthetic`, age and gender empty.
- **Temporal labels** `metadata/impact_temporal_labels_v001.jsonl`, SEED-Timeline format, one
  line per clip: `filename`, `overview_description` (the caption), `events` (`start_time`,
  `end_time` in seconds within the FBX, `description`): the source motion up to the hit, the
  hit and its reaction up to the outcome frame, and what follows (recovers / lies on the
  ground); `propagated_from_filename` null.
- **Training catalog** `metadata/impact_training_catalog_v001.jsonl`, in the shape the Kimodo
  fine-tune trainer reads (`finetune_data_examples`, style catalog + replay meta), one line per
  clip. Labels come in both forms (user, 2026-10-14):
  - **Overall**: `descriptions`, the four caption phrasings (the trainer samples one per step).
  - **Timed breakdown**: `events` (SEED-Timeline `start_time`, `end_time`, `description`) and the
    same segments as Kimodo multi-prompt `prompts` + `durations` (seconds, summing to the clip).
    Segments: the source motion up to the hit; the hit and its reaction up to the outcome frame;
    what follows (recovers and carries on / stays down). Each segment's text is a full sentence
    with the subject, e.g. "A person jogs forward." / "A person is shot in the left thigh by a
    small bullet and stumbles." / "The person recovers and keeps jogging."
  - Plus `id`, `fps`, `frames`, `duration_seconds`, `max_root_step_m`,
    `max_root_acceleration_mps2`, and the FBX path.
- **Training NPZ: not in this track** (user, 2026-10-14: "just fbx for now"). The trainer's NPZ
  (30-joint SOMA, native 30 fps) would need a UEFN-to-SOMA conversion; the catalog points at
  the FBX, and conversion is left to the training pipeline.
- Hosts: `-run=ImpactExport -Batch=<path> [-Start= -Count=]`, resumable like the batch runner
  (existing FBX files and rows are kept); shard outputs merge into one CSV and one JSONL each.

## Non-Functional Requirements
- **Throughput:** headless run substantially faster than real time; target ≥10k clips/night
  per machine (to be measured in Phase 1 spike and recorded).
- **Determinism:** same seed + index → same parameters; physics result reproducible on the
  same machine/build (cross-machine bitwise not required).
- **No shipping footprint:** new code is `UncookedOnly` / `Editor` like existing modules.
- **Memory:** no unbounded growth across a batch (assets unloaded/GC'd periodically).
- **Disk:** per-clip size measured and reported; batch warns before starting if estimate
  exceeds free space.

## Acceptance Criteria
1. A batch asset over ≥5 Kimodo-generated source anims runs headless to ≥1,000 clips unattended, with no
   editor interaction.
2. Each clip yields a playable `UAnimSequence` on the source skeleton and a valid v3 sidecar
   that round-trips.
3. Every clip's caption names its impactor, body region, source motion and outcome, and
   the sidecar records the impactor's size and description.
4. All four outcome classes appear in a mixed-intensity batch, and the distribution report
   shows them.
5. All four delivery modes produce clips; projectile clips show a real collision.
6. Killing the process mid-batch and rerunning completes the batch with no duplicates.
7. Same seed + index regenerates identical parameters (test) and visually identical motion
   (manual).
8. Panel preview shows hits with debug draw in PIE.

## Out of Scope
- Get-up / stand-up animations after knockdown (ragdoll settles; no authored recovery).
- Character-vs-character collisions or weapons models; impacts are abstract forces or simple
  projectile shapes.
- BVH export and SOMA/G1 versions of the clips (FBX on the UEFN mannequin only; FR9).
- Mirrored (`_M`) variants.
- Facial, cloth, hair simulation in the baked output (body skeleton only).
- Multiple characters per clip.
- Distributed farm orchestration beyond `-Start/-Count` sharding.
